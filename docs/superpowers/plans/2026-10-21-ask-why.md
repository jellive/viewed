# ask-why Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 데스크톱 앱에서 로컬로 연 리뷰의 diff 줄에 + 로 질문하면, 그 줄을 쓴 Claude 세션 기록 발췌와 git 근거로 도구 없는 `claude -p` 가 답하고 그 줄 아래 스레드에 붙는다.

**Architecture:** 데스크톱 main(CommonJS, `apps/desktop/ask/`)이 요청 검증·git 근거·세션 기록 탐색·Claude 실행을 전부 맡고 IPC `ask:start`/`ask:cancel` 두 개만 연다. 웹(`apps/web`)은 줄 좌표를 정해 보내고 스레드 상태(ReviewView 높이)와 화면만 맡는다. 근거 수집용 git 함수는 main 내부 전용(`askGit`) — 렌더러에 열린 `repo:git` op 목록은 그대로다.

**Tech Stack:** Electron 44.7.1 · Node 26(`node:test` 내장, 새 의존성 없음) · React 19.3.0 · Vite 8.3.4 · @playwright/test · Claude Code CLI ≥ 2.1.248(이 Mac 2.1.305)

**Spec:** `docs/superpowers/specs/2026-10-21-ask-why-design.md` — 각 태스크는 spec 절 번호를 단다. 구현자는 spec 을 같이 읽는다.

## Global Constraints

- **공개 레포다.** 커밋·테스트 픽스처에 `/Users/<이름>` 절대경로·실제 이메일·토큰·회사 이름을 넣지 않는다. 픽스처 경로는 `mkdtemp` 임시 폴더 또는 `/home/u/...` 같은 가짜, 이메일은 `you@example.com`. 끝에 `bash scripts/prepublish-scan.sh` 와 `--history` 가 통과해야 한다.
- 새 의존성 없음(pnpm 11 공개 24시간 보호를 우회하는 설정 금지). 데스크톱 단위 테스트는 `node:test`.
- Claude 인자는 정확히 `['-p', INSTRUCTION, '--restricted', '--tools', '', '--permission-mode', 'dontAsk', '--output-format', 'json', '--no-session-persistence', '--max-turns', '2', '--append-system-prompt', systemPrompt(lang)]`. `--bare` 금지. 플래그를 빼는 대체 경로 금지. cwd 는 호출마다 새 빈 임시 폴더, 끝나면 삭제.
- 최소 Claude Code `2.1.248`. 미만이면 실행하지 않는다.
- 마감 90_000ms — **실행 슬롯을 잡은 때부터**(spec §4). Claude 동시 실행은 앱 전체 1개, 나머지는 줄 선다.
- 한도(spec §6·§7·§9): 질문 ≤ 2000자 · `lineText` ≤ 2000자 · 이전 문답 ≤ 3쌍, 각 항목 ≤ 4000자 · 발췌 블록 1500자, 합계 30000자, 사람 메시지 2000자, 서브에이전트 브리프 3000자 · 사람 메시지 탐색 300기록 · 주변 코드 ±40줄(줄당 500자) · log 근거 8000자 · stdout 1MB · stderr 64KB · 공백 제외 8자 미만 줄은 세션을 찾지 않음 · 취소는 그룹에 SIGTERM, 2000ms 뒤 SIGKILL.
- 세션 기록(`~/.claude/projects`)은 **읽기만** 한다.
- 답은 텍스트로만 그린다 — 백틱만 `<code>`, HTML·링크 없음.
- + 는 데스크톱 브리지(`window.viewedDesktop.ask`)가 있고 **로컬로 열기에 성공한 리뷰**에만.

## Review Focus

1. **경로에 공백·한글·따옴표가 든 파일** — git `-L n,n:<path>`·JSON 이스케이프된 Edit 입력 모두에서 그 파일을 찾아야 한다. 테스트: Task 1(`공백 있는 파일.ts`), Task 2(따옴표·역슬래시 든 줄).
2. **CRLF 파일** — 렌더러가 보낸 줄과 main 이 읽은 줄이 `\r` 하나 차이로 어긋나 정상 질문이 `invalid` 로 거부되면 안 된다. 테스트: Task 5.
3. **macOS `/tmp`→`/private/tmp`, 심볼릭 링크 레포 폴더** — 세션 기록의 `file_path` 와 레포 경로가 realpath 차이로 안 맞아 못 찾으면 안 된다. 테스트: Task 2·3.
4. **rename 된 파일의 삭제 줄** — `previousPath` 와 merge-base 좌표로 물어야 한다. 테스트: Task 7.
5. **질문이 도는 중에 창을 다시 불러오거나 닫음** — claude 와 그 자식 프로세스가 남지 않는다. 테스트: Task 6.

```ts
type Side = 'L' | 'R';   // L = merge-base 쪽(삭제 줄), R = head 쪽(추가·문맥 줄)

type AskSource = { kind: 'session'; sessionId: string; at: number; subagent: boolean }
  | { kind: 'none'; reason: 'short-line' | 'not-found' | 'mixed' | 'no-human' | 'timeout' | 'no-time' };
type AskResult = { ok: true; answer: string; source: AskSource; account: string | null }
  | { ok: false; error: 'cancelled' | 'timeout' | 'not-installed' | 'too-old' | 'login' | 'invalid' | 'failed'; message?: string };
type AskStage = 'queued' | 'searching' | 'answering';   // main → renderer 진행 알림 { id, stage }
interface DesktopAsk { start(req: AskRequest): Promise<AskResult>; cancel(id: string): Promise<void>; onProgress(cb: (p: { id: string; stage: AskStage }) => void): () => void }
```
